# 本地增量备份 1.3.2

历次版本的逐条改动见[更新记录](CHANGELOG.md)。未正式发布的版本会单独标记。

为思源笔记桌面端创建本地、多版本目录快照。每份已完成快照都包含所选范围的文件；与上一份内容相同的文件通过硬链接共享存储。源文件与快照之间始终独立复制，修改笔记不会直接修改旧备份。

## 1.3.2 图标与反馈更新

顶栏现在使用“硬盘＋回环箭头”备份图标。运行中显示小圆点，失败或警告保留“!”提示；悬停可查看原因。快照列表可以按日期、快照名或备注搜索。最近成功结果会显示可用的复制、复用和耗时统计。

## 1.3.1 窗口修正

各页面现在共享固定外框，切换时不再忽大忽小。返回放在顶部左侧，缩小与关闭放在右侧。缩小后可从右下角恢复条继续打开，草稿和后台任务保留；关闭窗口不会取消备份。

## 1.3.0 界面更新

单击顶栏备份图标打开“备份工作台 · v1.3.2”。概览用于查看最近结果、保存位置和历史快照；“自动计划”设置位置与频率，“备份范围”选择目录及历史保留规则。切换标签不丢失未保存输入。右键顶栏图标仍可打开快捷菜单；命令面板和插件设置入口也能打开工作台。

安装后如果标题没有 v1.3.2，先重新启用插件或重启思源。集市介绍卡片由思源生成，与插件内部界面不同。

## 备份安全基础（1.2.0 引入）

- 新快照使用 v3 清单，记录每个文件的 SHA-256 内容指纹。复用旧文件前核对实际内容，不再仅凭文件大小和修改时间判断。
- 读取、复制、源文件变动、提交清单失败或取消时明确失败；失败快照不触发历史清理。
- 同一备份位置使用文件锁，避免备份、导出、备注和删除互相干扰。
- 扫描目录使用受控并发，缓存已创建的目录；设置页只读取快照清单，取消每次打开时对全部历史文件的空间遍历。
- 新的主题适配界面：最近结果、进度、取消、失败原因、快照校验和导出恢复说明；支持窄窗口。
- **自动清理默认关闭，包括从旧版升级时。** 需要清理时，在“历史保留与排除规则”中明确开启。
- **恢复改为校验并导出独立副本，退出思源后再替换目录。** 不再在思源运行期间覆盖工作空间。
- 测试改为加载当前项目代码，在独立临时目录中运行，不再硬编码已安装插件路径。

## 使用

1. 单击顶栏备份图标 → 自动计划。
2. 确认工作空间和备份保存位置。推荐另一块磁盘；目标不能与工作空间相同或互相嵌套。
3. 默认备份 `data`（笔记、附件和插件）以及 `conf`（配置）。按需开启 `history`、`repo`；勾选的目录不存在时会报错，请确认选择。
4. 点击“保存并备份”。备份期间可从设置或快照管理查看进度、取消本次备份。
5. 在快照管理中使用“校验”检查文件，再通过“恢复”导出。

定时备份默认每 60 分钟一次，并等待 2 分钟无键鼠操作。关闭定时与关闭“每日首启备份”是两个独立选项。每日成功日期只在备份成功后记录。

## 快照与校验

```text
SiYuanBackup/
├── snap-20261112-090000/
│   ├── data/
│   ├── conf/
│   └── _manifest.json
├── snap-20261112-100000/
└── backup.log
```

快照清单通过验证且不含 `_incomplete` 标记时，才显示为已完成。列表为保持快速响应，只读取清单和完成标记；**列表中出现快照不等于已经重新校验过所有文件**。“校验”和“恢复”会实际读取内容并检查文件清单。

v3 校验会核对路径、文件数、总字节数和逐文件 SHA-256。旧版 v2 快照仍支持导出，但没有创建时的内容指纹，只能检查结构、数量和大小，界面会明确提示这个限制。

“实际写入”表示创建该快照时复制的字节数，不是整个备份目录当前的物理磁盘占用。硬链接在快照之间共享 inode；不要直接编辑快照文件，否则其他共享该文件的历史快照也可能受影响。请先导出独立副本。

## 恢复笔记

1. 快照管理 → 校验 → 恢复 → 选择导出位置。
2. 插件会在选定位置下新建文件夹，校验并复制为独立文件。导出位置必须在工作空间与备份根目录之外；已有非空目录会被拒绝。
3. 确认导出成功，检查所需笔记和附件。
4. **完全退出思源笔记。** 将当前工作空间中要替换的对应目录移到其他安全位置留底，再放入导出的同名目录。例如要恢复 `data`，先保留原 `data`，再替换为导出的 `data`。
5. 重新打开思源，确认笔记、附件和配置。确认前保留原目录和导出副本。

导出本身不更改当前工作空间。恢复历史目录后，该时间点之后新增的文件不会出现在恢复后的目录中，所以必须保留当前目录作为退路。不要把含备份快照的整个文件夹覆盖回工作空间。

## 历史保留

默认不开启自动清理，所有历史保留，需要自行关注磁盘剩余空间。

开启后，仅在新快照完成并校验成功后清理同一工作空间的历史。策略优先选择最近 10 份，更早每天最新一份，再按“最多保留份数”截断；设为 5 时只保留最近 5 份。未知目录、损坏快照和未完成快照不会自动删除。备注不代表永久保留；需要长期保存的快照，请另行导出。

失败或取消产生的目录保留 `_incomplete` 标记，供排查。启动时不自动删除这些目录，快照管理中会提示异常条目。检查日志和原文件后，再自行决定如何处理。

## 异常处理与限制

- 磁盘容量不足、权限错误、符号链接和无法识别的文件类型会明确报错；不以静默跳过来制造成功结果。
- 工作空间、备份位置和导出位置应使用真实路径。当前版本严格拒绝路径中的符号链接组件；如果路径是别名，请改用真实目录。
- `.backup.lock` 是同一备份目录的操作锁。异常退出后可能残留。**先完全退出所有可能使用该目录的思源实例，并确认没有备份/导出进程运行，再检查并手动移除这个锁文件**；不要在操作进行中删除它。
- 硬链接由备份磁盘文件系统决定。在不支持硬链接的目标上会回退为独立复制，每份快照可能占用完整空间。源与备份位于不同磁盘并不妨碍快照之间建立硬链接。
- 默认排除临时目录、`corrupted/`、`.DS_Store`、`.lock`、`*.tmp`、`*.log` 和 `node_modules/`。额外排除内容不会被备份，请谨慎设置。
- 工作空间在运行中可能被思源和其他插件修改。本插件检查复制前后文件状态，并在结束时重扫；检测到变化会失败，请空闲时重试。它不提供数据库事务级快照，也无法保证对恶意外部进程的并发修改进行隔离。
- 内容校验和文件落盘确认需要额外读取及 I/O，不能承诺每次备份比旧版更快。小文件很多、机械硬盘或网络盘时尤其明显。设置页和扫描的优化可用下述基准复测。
- 本地备份无法防止备份磁盘一起损坏。重要资料请另外保留一份位于另一磁盘或异地的副本。

## 安装升级

此项目可生成安装包；开发时不直接覆盖正在使用的插件。

1. 从 [GitHub Releases](https://github.com/HIUIE/siyuan-incremental-backup/releases/latest) 下载附件 `package.zip` 或带版本号的插件 ZIP；不要把 GitHub 自动生成的 Source code 压缩包当作安装包。先保留旧版安装包和现有备份。
2. 完全退出思源，把 1.3.2 安装包中的文件解压到工作空间的 `data/plugins/siyuan-incremental-backup/`，覆盖同名插件程序文件。不要删除 `data/storage/petal/siyuan-incremental-backup/` 中的设置。
3. 重新打开思源，在设置中确认备份位置、范围及自动备份选项。
4. 先创建一份备份，执行“校验”，再导出到其他空目录检查。确认正常后继续日常使用。

## 开发与验证

不需要安装第三方依赖，使用支持 `fs.promises` 的 Node.js。开发验证环境为 Node 24；实际运行依赖思源桌面端内置的 Node/Electron，安装后仍需检查宿主兼容性。

```bash
node test-backup-plugin.js
node test-backup-safety.js
node test-plugin-load.js
node test-toolbar.js
node test-window.js
node test-plugin-management.js
node benchmark.js
node preview-ui.js
bash build.sh
node test-package.js
```

测试命令覆盖原有回归、安全故障注入、插件加载、顶栏图标、窗口导航和跨窗口快照管理。全部测试数据位于专属临时目录；不访问真实笔记。基准使用 1,209 个模拟文件比较固定的 v1.1.1 标签与当前核心，并输出 `artifacts/benchmark.json`。交互预览使用真实界面代码和演示 I/O，不连接思源，也不执行真实备份。

打包输出 `siyuan-incremental-backup-v1.3.2.zip`。已存在同名文件时脚本拒绝覆盖，便于保留可回退版本。发布时将同一安装包另存为 `package.zip` 上传 GitHub Release，供思源集市读取。首次集市收录需要向 `siyuan-note/bazaar` 的 `plugins.txt` 提交申请；本脚本不推送代码、不发布 Release，也不申请收录。
